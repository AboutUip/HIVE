## 结论

驻留一致性**不是**一个新的、更严格的级别。它落在**因果一致之下、纯最终一致之上**：比最终一致强，因为它用显式拒绝代替读旧值，且陈旧窗口有上界；比因果一致弱，因为读的动作不进依赖链，跨节点也不保证 read-your-writes。它的主张不是"更强"，而是"把一部分一致性难题移出数学，移进可运维的状态机"。

## 过程

先摆出常见的参照系：

| 级别 | 一句话 | 这套方案做到没有 |
| --- | --- | --- |
| 线性一致 | 所有操作看起来按真实时间顺序发生 | 没有。跨节点读会读到旧值。 |
| 顺序一致 | 所有操作按某个全局顺序发生 | 没有。各节点看到地址更新的先后可以不同。 |
| 因果一致 | 因果相关的操作全局有序 | 没有。读不产生依赖，写不记录它基于哪一版。 |
| read-your-writes | 自己写的一定读得到 | 同一台节点上有；换节点没有。 |
| 单调读 | 不会看到更旧的版本 | 同一台节点上有；换节点没有。 |
| **驻留一致性** | 每键恰有一个家；读要么拿到家数据、要么被拒绝/挂起；陈旧窗口以上报周期为上界 | — |
| 最终一致 | 停笔之后大家终会相同 | 有。静默后所有节点读到同一份。 |

与具体系统的对照：

| 系统 | 相近处 | 不同处 |
| --- | --- | --- |
| GFS / HDFS master | 目录只记位置，数据另有其主 | 它们的副本接读；这里灾备是冷备，不接读 |
| 主备复制 + 选举（ZooKeeper、Raft 系） | 单一写者、切换期间不服务 | 它们选主；这里转移所有权，且地址先挂起再换 |
| Dynamo / Cassandra | 时间戳 LWW、可调的陈旧读 | 它们多副本读；这里一读就一条路，读不落盘 |
| PNUTS | 每记录一个主、目录服务 | 它每条记录带版本向量；这里只有 HLC 时间戳 |
| Spanner TrueTime | 用时间做秩序 | 它靠硬件时钟给出全序；这里只承诺因果序，且无中心时间 |

## 例子

客户端在华北写下 K，马上跑到华东读。华东可能读到旧值或拒绝，但**不会**读到另一台节点杜撰的值；华北挂失后，华东读到的是「挂起」，而不是继续读一份没人负责的数据。这就是"以拒绝代替旧读"。

## 边界

- 上面这些名字只是为了定位，不代表实现上的借鉴关系。
- 保证的严格程度是一个刻度，不是勋章：驻留一致性的价值在**故障语义可运维**——挂失、挂起、装入、所有权转移都是有名有姓的状态，可以被观测（health、局面）和核对（不变式测试）。
- 若要更接近因果一致，下一步是让读也参与 HLC 的推进，并在写入时携带读过的版本。这是已知的改造路径，不是未解决的难题。
