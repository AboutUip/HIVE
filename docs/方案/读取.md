## 结论

读取只信本机。本机库里有，就用本机的。本机没有，就按本机地址副本直接去取，取回来的内容不写入本机。本机没有、地址里也没有，就拒绝。

## 过程

1. 本机库里有这份数据，直接使用。
2. 本机没有，查本机的地址副本。有地址，并且地址没有挂起，就到那个 IP 把数据取回来用。
3. 本机没有，地址副本里也没有，视为没有，拒绝。
4. 地址指向的节点上已经没有这份数据，视为没有，拒绝。不改去灾备里找。
5. 地址已经挂起，或者目标节点已经挂失，请求停在原地，不发往那台节点。

「从未写过」和「还在同步窗口里、别的节点尚未知道」使用同一种拒绝。窗口应当短于一个人在区域之间的移动。

IP 不通时，才按别名向中央要一次当前地址，更新本机持有的这一组别名，然后再连一次。见 [地址](地址.md)。

## 例子

华东要读林夏的城市。华东库里没有这份城市。华东的地址副本指向华北的 IP。华东向那个 IP 取值，得到「北京」，并且不把「北京」写入华东的库。

若华北还没上报，华东的地址副本里没有城市这一行。华东拒绝。调用方看到的是没有这份数据。

若华北已经挂失、地址已挂起，华东不向旧 IP 发请求。这次结果是挂起，和「没有」分开。

## 边界

- 同步窗口内，别的节点可能还拿着旧地址，于是取到旧值。这是方案接受的窗口。窗口长度可以调整，调整必须通知中央。见 [上报](上报.md)。
- 某一键被拒绝或挂起时，同一次读取里的其他键仍然返回。
- 对齐中的节点不能读取。它可以列已经拿到的临时名单。见 [加入](加入.md)。
- 灾备不在这条读取路径上。

调用见 [读取](../接口/服务节点/读取.md)。
