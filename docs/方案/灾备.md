## 结论

灾备和索引分开。索引的量级是地址。灾备留下可以用来恢复的稳定数据。它不是日志仓库，也不参与普通读取。

## 过程

1. 每台灾备事先声明自己负责哪些服务节点。负责范围在整理日志时生效。
2. 中央在更长的窗口里，把尚未用完的日志按用户和键收成最新的一份，交给负责其当前所在节点的灾备。
3. 不把原始日志打包送去，也不做压缩包。
4. 整理完成，这些日志从中央删除。要求留档时，删除前把它们写入日志文件。
5. 某个键再次被整理时，若它的所在节点不在这台灾备的负责范围内，这份记录离开。

只修改负责范围、又没有这个键的新日志，不会立刻重扫已经收好的记录，也不会把以前没有收进来的数据补回去。

新加入的服务节点不会自动进入任何灾备的负责范围。必须明确声明，并且至少再经过一次灾备整理。声明之前产生、又没有在声明之后再次被整理到的数据，不会补进这台灾备。

## 例子

灾备甲负责华北、华东、华南。中央每 6 秒把这段时间里的日志收成每个键的最新一份，交给灾备甲。林夏的城市若最后写在华东，灾备甲记下的所在节点就是华东，值是最新的那一份。

若把华南移出灾备甲的负责范围，华南上已有的记录不会立刻被扫掉。林夏下一次在华南改城市并被整理时，这份记录才离开灾备甲。

## 边界

- 普通读取找不到数据时，不改去灾备里找。见 [读取](读取.md)。
- 挂失恢复用的是这里的稳定数据，不是挂失节点自己的库。见 [恢复](恢复.md)。
- 装入前，中央若还留着相关日志，会先再整理一次，把已经收下、尚未整理的内容纳入。

调用见 [灾备](../接口/灾备.md)、[中央](../接口/中央.md)。核对时改负责范围见 [节点](../核对/节点.md)。
