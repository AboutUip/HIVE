## 结论

这套方案提供一种叫**驻留一致性**的保证：每个键在任一时刻最多有一个家；写入只在家里发生，也只有家里的那份会被读走；读到的值要么来自家，要么被拒绝或挂起——绝不会静默给出另一台节点上的旧值。地址的更新经过中央，一条写入在中央确认后，所有活着的节点都在一个上报窗口内指向新的家。

四个不变式：

| 编号 | 内容 |
| --- | --- |
| I1 | 指向挂失节点的中央索引一定处于挂起。 |
| I2 | 存在融合任务 ⇔ 恰好一台接替节点正在装入；没有任务时没有节点在装入。 |
| I3 | 融合期间，活着的节点上指向丢失节点的索引保持挂起，直到装入完成换上新地址。 |
| I6 | 灾备里的每一份稳定数据，家都在它声明的负责范围内。 |

另有三个性质由测试看管：I5 读到的值必来自它声称的节点；I7 静默之后所有节点读到同一份；I8 每台节点的发号严格单调，重启也不倒退。

## 过程

1. 写入只发生在服务节点上，先落本机库和待上报，再经中央确认。地址只会在中央改。
2. 挂失时，指向它的地址全部挂起，读请求停在原地，不发出。
3. 装入完成后，活着的节点统一换上新地址，挂起解除。
4. 任何一次操作结束（包括失败的），上面四个不变式都成立。它们在 [核对](../README.md) 里由随机操作逐项验证。

## 例子

- 华东写下 K，华北在上报窗口内读：华北可能还在读自己库里的旧 K——这是允许的陈旧窗口，以这台节点自己的上报周期为上界。
- 华北挂失：华东读指向华北的键，得到「挂起」，而不是旧值或错误值。
- 装入完成：所有节点读 K 都得到接替节点上的同一份值，旧碎片已经按时间去掉。

## 边界

- **不强于因果**：读的动作不进依赖链。客户端读后换节点写，不保证比读到的那份更新。
- **不保证跨节点 read-your-writes**：客户端从 A 节点写到 B 节点读，在上报窗口内可能读到旧值。
- **并发写同一键**：各自上报后时间更晚的留下。时间相同（两台节点从未互发过消息）时，后到中央的留下。
- **中央自己的故障在保证之外**：中央宕机时本机读写照常，跨机读被拒绝，灾备停摆；恢复后未确认的日志继续上报。见 [中央](中央.md)。
- 这套保证弱于因果一致，强于纯最终一致：拒绝是显式的，陈旧窗口有界，但没有读取依赖的跟踪。与已知系统的逐项对照见 [谱系](../谱系.md)。
