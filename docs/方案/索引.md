## 结论

索引只回答：这个用户的这个键，现在在哪一台、哪个别名、哪个 IP、什么时间、是否挂起。索引不存放值。

## 过程

1. 中央根据收下的日志更新全局地址。
2. 中央把这次变化派发给其他服务节点。交上这份日志的那一台不接收这次派发。
3. 因此，一台节点的持久索引里，通常没有它自己刚写下、还没被别的节点改过的那些键。那些键以本机库为准。
4. 派发时，时间不早于本机现有地址的，才覆盖本机地址。
5. 新地址指向别处，且时间不早于本机那份数据时，本机删掉这份过时数据。
6. 某次派发若有节点没收到，地址仍留在中央。这台节点下次按周期来上报时，中央把尚未确认送达的地址再送一次。

中央删除的是日志内容，不是地址。读取时不为了补地址去问中央。

列出「这个用户有哪些键」时，只翻持久索引会漏掉本机写下、又从未被派发回来的键。列完整名单时，在已有索引上临时补上本机库里的数据，地址指向自己。同一键两边都有时，以本机库里的这份为准。这张临时表用完即弃，不写回持久索引。新节点来拉索引时，用的也是这张临时表。

## 例子

林夏在华北写下 A、B、C。上报之后，华东和华南的地址把这三份指到华北。华北自己的持久索引里没有 A、B、C，因为这次派发跳过了交出日志的华北。华北读 A 时直接用本机库。

她后来在华东改了 C 并写下 D。派发之后，华北按时间去掉被盖住的旧 C，地址把 C 和 D 指到华东。没被改过的 A、B 仍在华北。

华东要列出林夏的全部键时，临时表里有持久索引中的 A、B，再加上华东库里的 C、D。列完之后，华东的持久索引条数不变。

## 边界

- 地址挂起时，读取不发出。见 [读取](读取.md)、[挂失](挂失.md)。
- 对齐中的节点收到的新地址先进缓冲区，不直接写入它的索引。见 [加入](加入.md)。
- 漏收的节点在下一次成功上报之前，仍用自己已有的地址。

调用见 [名单](../接口/服务节点/名单.md)、[上报](../接口/服务节点/上报.md)。
