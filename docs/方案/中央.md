## 结论

中央是唯一核心。节点挂失时，恢复的是服务节点上的用户数据，不是把中央换掉。中央的位置不因挂失和灾备而改变。

## 过程

1. 中央接收上报，过滤重复日志，维护全局地址，派发地址。
2. 中央按更长的窗口把日志收成稳定数据，交给灾备，然后删除这些日志。
3. 中央按每台节点的周期和容错判断是否还活着，并在连续两次索取失败后强制挂失。
4. 中央接纳新节点，分配编号，并在挂失后组织装入。

若要中央自己也能承受故障，在本方案之外为它增加灾备，或采用传统的全量复制。那是部署选择。

## 例子

华北挂失后，中央挑选华东装入林夏的数据。中央这台进程仍是原来的那一台。华东、华南继续向这台中央上报。

## 边界

- 方案外为中央增加的灾备或全量复制，不改变上面的读写、索引和节点恢复规则。
- 中央不长期保存日志内容。留档是额外的日志文件，库里的日志仍然删除。
- 应用不把中央当成读写入口。应用调用的是本机服务节点。

调用见 [中央](../接口/中央.md)。
