# 删除

| | |
| --- | --- |
| 这篇讲 | 一个键怎样从持有它的节点上消失，其他节点何时跟着消失。 |
| 读者 | 要删掉用户的某个键，并知道删除何时传播。 |
| 先读 | [地址](地址.md) |
| 接着读 | [中央](中央.md) |

[文档目录](../README.md)

## 结论

持有这份数据的节点可以删除这个键。删除与写入一样产生日志，时间规则相同。何时删除由业务决定。本方案只提供删除这个键的能力。

## 过程

1. 在持有该键的服务节点上删除。
2. 本机数据立即去掉。本机上对应的地址也立即去掉。
3. 一条删除日志留在待上报里。
4. 上报之后，中央按时间更新全局地址，并派发给其他节点。其他节点这时才从地址里去掉它。
5. 下一次灾备整理，才去掉灾备里的对应记录。时间更晚的记录不会被更早的删除盖住。

不能在一台并不持有该数据的节点上删除它。

## 例子

林夏的电话在华北。华北删除电话。华北的库里立刻没有电话。华东在这次删除上报并派发之前，仍可能按旧地址读到电话。派发之后，华东的地址里没有这个键，再读就是拒绝。灾备要等下一次整理，才去掉这份稳定记录。

在华东上删除电话会失败，因为电话不在华东的库里。

## 边界

- 空的键名不能删除。
- 每个键单独提交。后面的键失败时，前面已经删除的键保持删除。
- 业务上的保留期限、回收策略，不在本方案里。

调用见 [删除](../接口/服务节点/删除.md)。
