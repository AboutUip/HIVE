## 结论

用户在某台服务节点上写下的内容，只保存在这台节点的库里。同一份内容同时成为一条完整日志，留在这台节点的待上报队列中。这次访问不等待上报结束。

## 过程

1. 应用把用户和若干键值交给它所在的服务节点。
2. 这台节点把值写入本机库，并记下产生这一刻的 UTC。
3. 同样的内容进入待上报队列。队列一直留到中央确认。
4. 调用返回。其他节点此时还不知道这次写入。
5. 之后的上报把队列交给中央。中央收下之后，节点才从队列里删掉对应的项。节点不在送出之前自己删掉队列。
6. 中央滤掉已经收过的同一条日志，并仍然确认节点可以把它从队列里删掉。

只能写给正在服务或正在装入的服务节点。对齐中的节点、已挂失的节点、灾备，都不接受写入。

## 例子

林夏在华北写下城市「北京」、电话「13800000000」。这两份当时只在华北的库里，也在华北的待上报里。华东打开同一用户时，在华北完成上报并把地址派发出去之前，华东看不到它们。

她后来到华东，把城市改成「上海」，并新写备注。华东只保存新的城市和备注。同步完成前，华北仍是原来的城市和电话。

## 边界

- 空值不能写入。
- 一次写入里的每个键单独留下。后面的键失败时，前面已经留下的键还在。
- 同一台节点上连续两次落在同一毫秒时，后一次记成更晚的时刻。见 [时间](时间.md)。
- 待上报在挂失时不会补交。见 [挂失](挂失.md)。
