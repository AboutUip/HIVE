## 结论

中央、每一台服务节点、每一台灾备，各自一个进程，各自一个数据目录。应用只调用本机的服务节点。节点之间用 HTTP 通信，请求头是 `Authorization: Bearer <token>`。

需要 Node.js 20 或更高版本。入口是包名 `hive`。

## 过程

1. 先启动中央，在 `nodes` 里声明全部服务节点和灾备。
2. 用中央实际监听的主机和端口，启动每台灾备、每台服务节点。
3. 灾备和服务节点启动时向中央登记自己的 `主机:端口`。
4. 应用调用本机服务节点的 `write`、`read`、`remove`、`list`。上报由这台节点按间隔自己做，也可以主动调用 `report`。

默认把局面写在该进程数据目录的 `state.json`。要换 SQLite 时见 [存储](存储.md)。

中央是唯一仲裁者。它自己的高可用放在方案外面。见 [中央](../方案/中央.md)。

## 例子

```javascript
import { startCentral, startDr, startService } from 'hive'

const central = await startCentral({
  dataDir: './data/central',
  token: '集群令牌',
  nodes: [
    { id: 'svc-a', name: '华北节点', role: 'service', region: '华北', alias: 'svc-a' },
    { id: 'svc-b', name: '华东节点', role: 'service', region: '华东', alias: 'svc-b' },
    { id: 'dr-1', name: '灾备甲', role: 'dr', region: '集中', alias: 'dr-1', covers: ['svc-a', 'svc-b'] }
  ]
})

const link = { host: central.host, port: central.http.port }

await startDr({
  dataDir: './data/dr',
  token: '集群令牌',
  id: 'dr-1',
  name: '灾备甲',
  region: '集中',
  covers: ['svc-a', 'svc-b'],
  host: '127.0.0.1',
  central: link
})

const north = await startService({
  dataDir: './data/svc-a',
  token: '集群令牌',
  id: 'svc-a',
  name: '华北节点',
  region: '华北',
  central: link
})

await north.write({ userId: '林夏', entries: [{ key: '城市', value: '北京' }] })
```

华东用同一个 `link` 和令牌启动之后，才能按地址读到华北写下的城市。

## 边界

- 三个进程的 `token` 必须相同。令牌不对时，对方返回 `令牌不对`。
- 监听地址默认 `127.0.0.1`。端口默认 `0`，由系统分配。实际端口在返回对象的 `http.port`。
- `createHive` 不在这条路径上。见 [创建](../核对/创建.md)。
