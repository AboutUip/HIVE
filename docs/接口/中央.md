## `startCentral`

启动中央。配置里的节点先记在中央，地址等到对方来登记才填上。

### 签名

```javascript
import { startCentral } from 'hive'

const central = await startCentral(options)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `dataDir` | 字符串 | 是 | 中央自己的数据目录。局面写在其中的 `state.json`。 |
| `token` | 字符串 | 是 | 集群令牌。节点之间每次请求都要带上。 |
| `nodes` | 数组 | 是 | 事先声明的节点。至少一台，且至少一台 `role` 为 `service`。 |
| `host` | 字符串 | 否 | 监听地址。默认 `127.0.0.1`。 |
| `port` | 整数 | 否 | 监听端口。默认 `0`，由系统分配。 |
| `reportIntervalMs` | 整数 | 否 | 默认上报间隔。默认 `2000`。每台节点以后可以单独改。 |
| `drIntervalMs` | 整数 | 否 | 灾备整理间隔。默认 `6000`。 |
| `toleranceMs` | 整数 | 否 | 超过上报间隔后再等这么久仍无上报，才开始索要。默认 `1000`。连续两次联系不上就挂失。 |
| `checkIntervalMs` | 整数 | 否 | 中央自己检查存活、整理灾备、续上未完成装入的间隔。默认 `1000`。 |
| `newNodeId` | 字符串 | 否 | 新节点编号样式。`{seq}` 会被序号替换。默认 `svc-{seq}`。 |
| `nodeSeq` | 整数 | 否 | 新节点起始序号。默认从 `1` 开始。 |
| `retention` | 布尔 | 否 | 为真时，整理过的日志在删除前追加写入日志文件。 |
| `retentionFile` | 字符串 | 否 | 日志文件路径。默认是数据目录下的 `retained.log`。 |
| `retentionMaxBytes` | 整数 | 否 | 留档文件超过这么多字节后轮转成 `retained.log.1`。默认 `10485760`。 |
| `clock` | 函数 | 否 | 返回当前毫秒。只用于存活和整理时刻。默认 `Date.now`。 |
| `store` | 对象 | 否 | 自己的存储。不传时使用 `FileStore`。见 [存储](存储.md)。 |
| `tls` | 对象 | 否 | TLS 配置。给了它监听走 HTTPS，发出的调用也走 HTTPS。见 [运维](运维.md)。 |
| `callTimeoutMs` | 整数 | 否 | 向节点调用的超时。默认 `2000`。推送类调用失败自动重试一次。 |

`nodes` 的每一项：

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 编号。集群内唯一。 |
| `name` | 字符串 | 是 | 给人看的名字。 |
| `role` | 字符串 | 是 | `service` 或 `dr`。 |
| `region` | 字符串 | 是 | 区域名。 |
| `alias` | 字符串 | 否 | 稳定别名。省略时等于 `id`。 |
| `covers` | 字符串数组 | 灾备要有 | 这台灾备负责哪些服务节点编号。服务节点忽略这项。 |
| `address` | 字符串 | 否 | 启动前就知道的 `主机:端口`。通常留空，等对方登记。 |

### 返回

中央对象。`central.host` 是监听主机。`central.http.port` 是实际端口。把这两项交给灾备和服务节点的 `central`。

`close()` 停掉检查定时器和监听，并关闭存储。

### 抛出

| 条件 | `message` |
| --- | --- |
| 没有 `dataDir` | `要指定数据目录` |
| 没有 `token` | `集群令牌不能是空的` |
| `nodes` 不是非空数组 | `配置里至少要有一台节点` |
| 没有服务节点 | `配置里至少要有一台服务节点` |
| 某一项缺少编号、名称、区域或别名 | `…缺少编号、名称、区域或别名` |
| `role` 不是 `service` 或 `dr` | `…的角色只能是 service 或 dr` |
| 间隔类字段不是不小于 1 的整数 | `上报间隔必须是不小于 1 的整数`，或对应字段名 |

### 调用返回时

- 数据目录里已有局面时，接着用，不重新播种。
- 还没有局面时，写入这些节点。状态是正在服务，地址可以仍为空，上次上报时刻为 `0`。
- 上次上报时刻为 `0` 的节点不会被立刻挂失。它第一次登记后才开始计算期限。
- 若目录里还有未完成的装入，启动时会接着装。
- 已经挂失的编号再来登记，状态仍是挂失。

### 例子

```javascript
const central = await startCentral({
  dataDir: './data/central',
  token: '集群令牌',
  reportIntervalMs: 2000,
  drIntervalMs: 6000,
  toleranceMs: 1000,
  nodes: [
    { id: 'svc-a', name: '华北节点', role: 'service', region: '华北', alias: 'svc-a' },
    { id: 'dr-1', name: '灾备甲', role: 'dr', region: '集中', alias: 'dr-1', covers: ['svc-a'] }
  ]
})

const link = { host: central.host, port: central.http.port }
```

留档时加上 `retention: true`。整理进灾备之后，日志仍从中央删除，删除前每一行追加一个 JSON：`userId`、`key`、`value`、`op`、`updatedAt`、`source`。
