## `write`

把若干键值写入本机库，并放进待上报。调用返回时，其他节点还不知道这次写入。

### 签名

```javascript
await node.write({ userId, entries })
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `userId` | 字符串 | 是 | 用户是谁。首尾空白会被去掉。 |
| `entries` | 数组 | 是 | 每一项是 `{ key, value }`。键和值都会转成字符串。键去掉首尾空白。 |

`value` 不能是空字符串。

### 返回

```javascript
{ written: ['城市', '电话'] }
```

`written` 是这次写下的键名，顺序与 `entries` 相同。

### 抛出

| 条件 | `message` |
| --- | --- |
| 还在对齐 | `华北节点还没投入服务`，名字换成这台节点 |
| 没有用户 | `先写上用户是谁` |
| `entries` 为空或不是数组 | `这次没有要写入的内容` |
| 某一项没有键名 | `每一份数据都要有名字` |
| 某一项的值为空 | `城市 还没有内容`，键名换上实际的键 |

后面的键抛出时，前面已经写下的键留在本机和待上报里。

本机存储抛错，且不是上面这些业务校验时，这台节点会向中央申请挂失，然后把原来的错误交给调用方。

### 调用返回时

每个键单独提交：本机碎片和对应的待上报要么一起留下，要么一起不留。时间是这台节点发下的 HLC 时间戳，物理位来自 `now()`。同一节点上的发号严格递增。

待上报留到中央确认。见 [上报](上报.md)。

### 例子

```javascript
await north.write({
  userId: '林夏',
  entries: [
    { key: '城市', value: '北京' },
    { key: '电话', value: '13800000000' }
  ]
})
```
