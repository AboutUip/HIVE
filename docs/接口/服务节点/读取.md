## `read`

先看本机库，再看本机地址，然后按 IP 直接向持有数据的那一台要。取回来的内容不写入本机。

### 签名

```javascript
const { results } = await node.read({ userId, keys })
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `userId` | 字符串 | 是 | 用户是谁。 |
| `keys` | 字符串数组 | 是 | 要读的键。 |

### 返回

`results` 与 `keys` 一一对应。某一键被拒绝或挂起时，整个调用仍然成功。

每一项：

| 字段 | 何时有 | 说明 |
| --- | --- | --- |
| `key` | 总是 | 请求的键。 |
| `source` | 总是 | `local`、`remote`、`rejected`、`suspended`。 |
| `message` | 总是 | 给人看的一句说明。 |
| `value` | `local`、`remote` | 取到的值。 |
| `storedLocally` | `local`、`remote` | 本机库里有则为 `true`。按地址取回则为 `false`。 |
| `fromNodeId` | 本机有，或按别名取回 | 数据所在节点。按原 IP 直接取回时不带这项。 |
| `fromIp` | 有地址时 | 取值用的 `主机:端口`。 |
| `via` | 取到值时 | `local`、`ip` 或 `alias`。 |

`source`：

| 值 | 含义 |
| --- | --- |
| `local` | 本机库里有。 |
| `remote` | 按地址取回，没有写入本机。 |
| `rejected` | 视为没有。包括地址里没有、对方已经没有、别名核对后仍不可达。 |
| `suspended` | 地址已挂起，或目标已挂失、还在对齐。请求没有发出。 |

`via` 为 `alias` 时，原来的 IP 不通，已经按别名向中央要过一次新地址，更新了本机上同一别名的地址，然后再读了一次。

### 抛出

| 条件 | `message` |
| --- | --- |
| 还在对齐 | `华北节点还没投入服务` |
| 没有用户 | `先写上用户是谁` |
| `keys` 为空或不是数组 | `先指定要读取的键` |

键名为空时，对应结果是 `{ key, source: 'rejected', message: '没有键名' }`，不抛出。

### 调用返回时

本机库和持久索引的条数不变。按别名更新过的 IP 会写进本机地址副本。远程取回的值不写入本机。

### 例子

```javascript
const { results } = await east.read({ userId: '林夏', keys: ['城市'] })
```

华北已经上报、地址已派发时，华东得到：

```javascript
{
  key: '城市',
  value: '北京',
  source: 'remote',
  storedLocally: false,
  fromIp: '127.0.0.1:4001',
  via: 'ip',
  message: '从 127.0.0.1:4001 取回，未写入本机'
}
```

地址还没到华东时：

```javascript
{
  key: '城市',
  source: 'rejected',
  message: '本地没有，索引里也没有，拒绝'
}
```
