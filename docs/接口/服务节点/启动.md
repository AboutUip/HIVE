## `startService`

启动本机服务节点，并向中央登记这次绑定的 `主机:端口`。

### 签名

```javascript
import { startService } from 'hive'

const node = await startService(options)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `dataDir` | 字符串 | 是 | 这台节点自己的数据目录。 |
| `token` | 字符串 | 是 | 与中央相同的令牌。 |
| `central` | `{ host, port }` | 是 | 中央的地址。 |
| `id` | 字符串 | 加入已有节点时必须 | 与中央配置里的编号一致。`join: true` 时由中央分配。 |
| `name` | 字符串 | 加入已有节点时必须 | 节点名称。 |
| `region` | 字符串 | 是 | 区域。新节点也要给区域。 |
| `alias` | 字符串 | 否 | 省略时等于 `id`。新节点的别名等于中央分配的编号。 |
| `host` | 字符串 | 否 | 监听地址。默认 `127.0.0.1`。 |
| `port` | 整数 | 否 | 监听端口。默认 `0`。登记上去的就是这次绑定的地址。 |
| `reportIntervalMs` | 整数 | 否 | 本机多久把待上报交给中央。默认 `2000`。 |
| `now` | 函数 | 否 | 写下数据时取 UTC。默认 `() => new Date()`。可以返回 `Date`，或能被 `Date.parse` 解析的字符串。 |
| `join` | 布尔 | 否 | 为真时作为新节点加入。先拉临时索引，`ready()` 之后才接待读写。 |
| `helloTimeoutMs` | 整数 | 否 | 连不上中央时最多再试这么久。默认 `5000`。 |
| `store` | 对象 | 否 | 自己的存储。不传时使用 `FileStore`。 |

### 返回

服务节点对象。应用之后调用的就是这个对象的 `write`、`read`、`remove`、`list`、`report`、`ready`、`setReportInterval`、`close`。

### 抛出

| 条件 | `message` |
| --- | --- |
| 没有 `dataDir` | `要指定数据目录` |
| 没有 `token` | `集群令牌不能是空的` |
| `central` 缺少主机或端口 | `要写上中央的地址` |
| 不是加入，且缺少编号、名称或区域 | `服务节点要有编号、名称和区域` |
| 加入时没有区域 | `新节点要落在一个区域` |
| 这个编号在中央已经挂失 | `这台节点已挂失，清空数据目录后用 join 重新加入` |
| 超时仍联系不上中央 | 最后一次连接错误 |

### 调用返回时

- 已有节点：中央记下新的 `主机:端口`，上次上报时刻改成现在，重试次数清零。本机按 `reportIntervalMs` 开始定时上报。数据目录里已有的碎片还在。
- `join: true`：状态为对齐中。本机索引里是来源节点的临时表。还不能 `write`、`read`、`remove`。可以 `list`。要再调用 [就绪](就绪.md)。
- 同一毫秒内的连续写入会把后一次记成晚 1 毫秒。这个「上一次时间」会从数据目录里恢复。

### 例子

```javascript
const north = await startService({
  dataDir: './data/svc-a',
  token: '集群令牌',
  id: 'svc-a',
  name: '华北节点',
  region: '华北',
  host: '127.0.0.1',
  central: { host: central.host, port: central.http.port }
})
```

作为新节点：

```javascript
const west = await startService({
  dataDir: './data/svc-new',
  token: '集群令牌',
  region: '西南',
  name: '西南节点',
  join: true,
  central: { host: central.host, port: central.http.port }
})
```

`west.id` 在返回后才是中央分配的编号。
