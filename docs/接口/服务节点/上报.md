## `report`

把当前待上报交给中央。队列是空的，也会联系一次。启动之后，节点会按 `reportIntervalMs` 自己调用。

### 签名

```javascript
const { reported } = await node.report()
```

### 参数

无。

### 返回

```javascript
{ reported: 2 }
```

`reported` 是这次送出的条数。空上报为 `0`。

对齐中的节点直接返回 `{ reported: 0 }`，不联系中央。

### 抛出

中央拒绝时抛出中央的 `message`，例如这台节点 `现在不能上报`。网络失败时为 `无法连接` 或 `连接超时`。

存储抛错且不是业务校验时，会先向中央申请挂失。

### 调用返回时

- 中央已确认的那些项从本机待上报里删除。重复送到的日志也会被确认，从而离开队列。
- 中央已按时间更新全局地址，并尝试把地址派发给其他正在服务或正在装入的节点。交出这次日志的本机不接收这次派发。
- 某台节点这次没收到派发时，地址留在中央，等它下一次成功上报再送。
- 中央把这台节点的上次上报时刻改成现在，重试次数清零。

### 例子

```javascript
await north.write({ userId: '林夏', entries: [{ key: '城市', value: '北京' }] })
await north.report()
```

此后华东的 `read` 才能按地址取到「北京」。
