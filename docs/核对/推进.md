[文档目录](../README.md)。行为见 [上报](../方案/上报.md)、[灾备](../方案/灾备.md)。

生产里没有拍。间隔是毫秒，由各进程自己的定时器推进。

## `tick`

当前拍。

### 签名

```javascript
const beat = hive.tick()
```

### 参数

无。

### 返回

从 0 开始的整数。`reset()` 之后为 0。

### 抛出

没有局面时抛出 `这个目录还没有局面，先 reset()`。已关闭时抛出 `库已关闭`。

### 调用返回时

不推进，不上报。

### 例子

```javascript
hive.reset()
hive.tick()
```

## `advance`

向前走若干拍。

### 签名

```javascript
const result = hive.advance(mode)
```

### 参数

| mode | 行为 |
| --- | --- |
| `'one'` | 走 1 拍。 |
| `'sync'` | 一直走到有一台服务节点成功上报为止。最多再走「当前全局上报周期 + 1」拍。 |
| `'dr'` | 一直走到拍数能被灾备周期整除的那一拍，并在那一拍整理灾备。最多再走「灾备周期 + 1」拍。 |

### 返回

普通结果，含 `message` 和 `state`。

### 抛出

| 条件 | `message` |
| --- | --- |
| `mode` 不是 `'sync'` 或 `'dr'`，也不是 `'one'` | `未知的推进方式` |
| 走到上限仍没有目标 | `这一轮没有走到目标窗口` |

走不到目标时，已经走过的拍仍然生效，其中可能已经发生索取、重试或挂失。

### 调用返回时

每一拍里，正在服务或正在装入的节点若到达自己的上报周期，就向中央上报。空队列也算上报成功，并记下这一拍。数据库被标记为不可达的节点，会在这一拍自己申请挂失。

拍数能被灾备周期整除时，中央把还留着的日志整理进灾备，然后删除这些日志。

`advance('sync')` 在任意一台节点上报成功时就返回。它不表示每一台都上报了。一台节点不可达时，其他节点仍可能让这次调用成功。

容错来自配置里的 `reportTolerance`。没有单独的运行时修改方法；改配置后，下一次 `reset()` 生效。期限之前没报到，只记一次没收到。到达期限后每拍再要一次；第 2 次仍要不到，中央以「未按预期上报」强制挂失。

`state.nextSyncIn` 和 `state.nextDrIn` 按全局周期估算，不按某一台单独改过的周期计算。

### 例子

```javascript
hive.write({ nodeId: 'svc-a', userId: '甲', entries: [{ key: 'A', value: '甲一' }] })
hive.advance('sync')
hive.advance('dr')
```
