这三个方法只用于核对。它们不代替 `lose`。不可达要等上报期限。库损坏要等节点自己在下一次接触时申请挂失。标记只在当前进程里有效。重新打开后，节点按库里的状态继续，并视为可以访问。

## `setReachable`

标出一台节点的服务器能否访问。

### 签名

```javascript
hive.setReachable(nodeId, reachable)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `nodeId` | 字符串 | 是 | 节点。 |
| `reachable` | 布尔 | 是 | `false` 表示服务器无法访问。`true` 恢复。 |

### 返回

普通结果。

### 抛出

没有这台节点时抛出 `没有这台节点`。

### 调用返回时

`false` 时，上报要不到它，读取时 IP 也不通。它不会立刻变成挂失，要等期限、索取和重试。它也不参与接替和提供索引。

### 例子

```javascript
hive.setReachable('svc-a', false)
hive.advance('sync')
```

## `breakDatabase`

标记一台服务节点的库不可达。

### 签名

```javascript
hive.breakDatabase(nodeId)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `nodeId` | 字符串 | 是 | 服务节点。 |

### 返回

普通结果。

### 抛出

不是服务节点时抛出 `这里只标记服务节点的库`。

### 调用返回时

调用本身不挂失。下一次 `advance`，或对它执行 `write`、`read`、`remove`、`list` 时，它以「数据库不可达」申请挂失。对它的读写会在申请之后抛出。

`getState()` 对这种节点不再读取库内容。对应节点带 `dbBroken: true`，本地数据列表为空。

### 例子

```javascript
hive.breakDatabase('svc-a')
hive.advance('one')
```

## `setIndexLink`

标出一台服务节点是否收得到派发的地址。

### 签名

```javascript
hive.setIndexLink(nodeId, up)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `nodeId` | 字符串 | 是 | 服务节点。 |
| `up` | 布尔 | 是 | `false` 表示先别写入它的索引。`true` 表示链路恢复。 |

### 返回

普通结果。

### 抛出

不是服务节点时抛出 `索引只派发给服务节点`。

### 调用返回时

`false` 时，派给这台节点的地址先留在中央，不写入它的索引。`true` 之后，要等它下一次成功上报，中央才把这些地址补送过去。读取不会为了补地址去问中央。

### 例子

```javascript
hive.setIndexLink('svc-b', false)
hive.advance('sync')
hive.setIndexLink('svc-b', true)
hive.advance('sync')
```
