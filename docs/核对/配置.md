这组字段只给进程内核对使用。生产进程的间隔和节点在 [中央](../接口/中央.md) 的参数里，单位是毫秒，不读这个文件。

## 字段

### 签名

配置是一个对象。默认文件是仓库根目录的 `config/default.json`。

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `syncPeriod` | 整数 | 是 | 全局上报周期，单位是拍。默认 `2`。 |
| `drPeriod` | 整数 | 是 | 灾备整理周期，单位是拍。默认 `6`。 |
| `reportTolerance` | 整数 | 是 | 容错拍数。默认 `1`。期限是「上次成功上报的拍 + 这台节点的周期 + 容错」。 |
| `nodeSeq` | 整数 | 是 | 下一台新节点的序号。默认 `4`。 |
| `newNodeId` | 字符串 | 是 | 新节点编号样式，含 `{seq}`。默认 `svc-{seq}`。 |
| `newNodeIp` | 字符串 | 是 | 新节点地址样式，含 `{seq}`。默认 `10.{seq}.0.1`。 |
| `actor` | 对象 | 是 | `{ userId, nodeId }`。默认用户「甲」在 `svc-a`。 |
| `nodes` | 数组 | 是 | 起始节点。每项含 `id`、`name`、`role`、`region`、`ip`、`alias`、`covers`。 |

`role` 为 `service` 或 `dr`。灾备的 `covers` 是它负责的服务节点编号。

### 返回

`loadConfig` 返回同一形状的对象。

### 抛出

缺字段、编号重复、`covers` 指向不存在的服务节点时，`loadConfig` 抛出。

### 调用返回时

这些名字、地址、负责范围和周期都来自配置，不写在引擎里。改文件之后，下一次 `reset()` 生效。日志默认不留档。

### 例子

默认四台：

| id | 名称 | 角色 | 区域 | IP | 别名 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `svc-a` | 华北节点 | 服务 | 华北 | `10.1.0.1` | `svc-a` | 正在服务 |
| `svc-b` | 华东节点 | 服务 | 华东 | `10.2.0.1` | `svc-b` | 正在服务 |
| `svc-c` | 华南节点 | 服务 | 华南 | `10.3.0.1` | `svc-c` | 正在服务 |
| `dr-1` | 灾备甲 | 灾备 | 集中 | `10.9.0.1` | `dr-1` | 正在服务 |

`dr-1` 负责 `svc-a`、`svc-b`、`svc-c`。第一台新节点是 `svc-4`，地址 `10.4.0.1`。用过之后序号加 1。
