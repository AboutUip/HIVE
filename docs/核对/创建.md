## `createHive`

打开或接着打开一个数据目录里的核对局面。

### 签名

```javascript
import { createHive, Hive } from 'hive'

const hive = createHive({ dataDir, config, configPath, now, retentionFile, store })
const same = new Hive(dataDir, options)
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `dataDir` | 字符串 | 是 | 数据目录。默认存储把整个局面写在 `state.json`。 |
| `config` | 对象 | 否 | 配置。传入之后不再读文件。形状见 [配置](配置.md)。只在 `reset()` 时使用。 |
| `configPath` | 字符串 | 否 | 配置文件路径。默认是仓库里的 `config/default.json`。与 `config` 同时传入时，以 `config` 为准。 |
| `now` | 函数 | 否 | 节点取数据时间。默认 `() => new Date()`。可以返回 `Date`，或能被 `Date.parse` 解析的字符串。 |
| `retentionFile` | 字符串 | 否 | 要求留档时写入的文件。默认是 `dataDir/retained.log`。 |
| `store` | 对象 | 否 | 自己的存储。不传时使用 `FileStore`。见 [存储](../接口/存储.md)。 |

### 返回

核对对象。构造时就打开存储。

### 抛出

| 条件 | `message` |
| --- | --- |
| 没有 `dataDir` | `要指定数据目录` |
| 存储缺方法 | `存储缺少方法：…` |

目录里还没有局面时，构造本身不抛出。第一次 `getState()` 或业务调用抛出 `这个目录还没有局面，先 reset()`。

### 调用返回时

目录里已有局面时，直接接着用，不必 `reset()`。`now` 只决定数据上的 UTC，不推进拍，也不和中央协商。同一节点上，若这次取出的时间不晚于它上一次写下的时间，记成晚 1 毫秒。这个「上一次」从目录里已有的时间恢复。

### 例子

```javascript
const hive = createHive({ dataDir: './data' })
hive.reset()
```

## `loadConfig`

读取并检查一份核对配置。

### 签名

```javascript
import { loadConfig, defaultConfigPath } from 'hive'

const config = loadConfig(source)
const path = defaultConfigPath
```

### 参数

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `source` | 字符串或对象 | 是 | 文件路径，或已经解析的配置对象。 |

### 返回

检查过的配置对象。`defaultConfigPath` 是默认文件的绝对路径。

### 抛出

缺字段、编号重复、负责范围指向不存在的服务节点时抛出。

### 调用返回时

不写盘，不改变已打开的局面。要让新配置生效，再 `reset()`。

### 例子

```javascript
const config = loadConfig(defaultConfigPath)
const hive = createHive({ dataDir: './data', config })
```
